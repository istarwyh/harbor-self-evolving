## Selection, persistent tasks and saved-version recovery — 2026-09-05

This iteration addresses the subsequent usability review. It does **not** remove the upstream ACP blocker or establish a passing Candidate baseline.

- **One selection model:** query snapshots resolve their exact Host-owned members into the same ID set that controls row checkboxes. All-filtered selection, count, exclusions and the prepared AI reference now agree. Pagination/sorting preserve the frozen membership; changes to membership filters, Job, workspace or Session invalidate it and late responses. A prepared Composer reference is not silently changed.
- **Persistent task entry:** the Copilot contains a separate Background tasks panel outside its discussion/expanded-body conditions. Its Session/project-owned list comes from durable operation journals, not the current AI answer. It keeps polling when collapsed and restores after a page/Host restart. Accepted/running/cancelling/terminal states, failed-quality boundaries, explicit cancellation and exact Job navigation remain reachable while reading another discussion. Read failures retain visibly stale records and disable recovery/cancellation actions until a fresh read.
- **Progress and partial evidence:** bounded lifecycle reads expose actual phase counts, completed/total tasks and update time. Live broker request counts and the enforced request ceiling are shown when available, not inferred token/currency costs. Verified Job navigation is independent of lifecycle validity, so corrupt/incomplete progress does not hide the evidence needed to investigate it. No summary or partial artifact is promoted to a passing evaluation.
- **Reviewed recovery:** read-only inspection reports recorded PID/process group and exact remaining Compose containers/networks/volumes. Releasing the exact diagnostic claim requires an unexpired, explicitly reviewed inspection hash and a fresh Host-side recheck. It retains FAILED/CANCELLED/INTERRUPTED, writes a separate audit receipt, never retries and never deletes Docker resources. A late spawn checkpoint is preserved even when cancellation was acknowledged first.
- **Runtime identity:** new diagnostics pin a local Unix socket endpoint (not a mutable Docker context name). Host machine/process-domain and Docker daemon identities are hashed, checked before launch and compared during inspection. Raw hardware IDs, daemon endpoints and credentials are not journaled. Remote/TLS Docker is rejected during preflight until immutable transport/cleanup ownership is supported.
- **Saved-version continuation:** successful browser saves bind the exact Session/workspace/historical Job and persist metadata-only receipts. Governance reload rechecks Evaluator identity/digest and the full Stack file fingerprint before restoring source and the planning action. Changed/missing versions remain explicitly unverified and cannot prepare the old plan. A later authoritative history-read failure also revokes an earlier verified receipt's source display and planning eligibility while retaining the successful save identity; a successful recheck restores eligibility. Failed receipt persistence is reported as a successful source save with unavailable continuation, never an invitation to save again. Old saves without a journal are not retrospectively attributed to a Session.

## Bounded diagnostic and saved-version follow-through — 2026-09-05

Implemented: **frozen selection → AI proposal → deterministic preview → explicit confirmation → owned background Operation → explicit result navigation**. This is not a claim that the complete AC-04 or the upstream Candidate runtime passes.

- The Trials view offers a one-click diagnostic planning question for 1–12 selected tasks. It prepares the Composer only; AI produces a typed proposal, not a direct evaluation call. Changing checkboxes or filters withdraws an obsolete page snapshot without replacing a reference already prepared in the Composer.
- Host execution resolves all frozen selection members independently of the model-facing bounded evidence reader. Read-only preflight maps lifecycle IDs to unique registered Dataset tasks and verifies Candidate, Dataset, Stack, source revision, historical model identity, runtime prerequisites and effective quotas. A new immutable subset, with new Dataset identity and provenance, is materialized only after confirmation. Job-start checks revalidate pins before Trial execution.
- One draft has one stable Operation/Job identity. Exclusive immutable sequence journals and a cross-Host workspace claim prevent duplicate starts. The asynchronous process remains owned; cancellation and plugin disposal await process-group termination and close the model lease. Restart does not resume or retry work automatically. Unknown ownership and uncertain Docker cleanup retain a recovery barrier.
- Limits: at most 12 tasks, 2 concurrent tasks, one attempt, no automatic retry, 900-second execution timeout, at most 96 Candidate Host gateway requests and 1 MiB returned per request (further clamped by Host limits). These are **not** token or currency caps. Independently called business/verifier APIs are not covered by the gateway quota, and their costs are unknown.
- The card follows the same Operation with ordered, abortable 1.5-second polling, including after collapse/reconnect. It distinguishes accepted, running, cancelling, cancelled, failed and ownership-unknown states. A completed evaluation with infrastructure exceptions is visibly different from a successful quality result. Only clicking **View diagnostic results** navigates to its exact new Job; nothing switches pages automatically.
- A successful Evaluator save now offers **View new version** and **Plan meta-evaluation and a fresh baseline with AI**. The read-only snapshot and plan use actual receipt identities while preserving the historical Job reference. The successful receipt remains visible if the subsequent governance refresh fails. This does not execute meta-evaluation or generate a baseline.

## Usability follow-through — 2026-09-05

The earlier iteration below targeted **select → ask → follow up → review/edit → save**. Bounded execution follow-through is recorded above.

- Home now explains the three-step journey and offers an entry into existing results. Suggested questions follow the selected object; Home no longer asks why an unselected Trial lost points. Technical identity and operation details are collapsed by default.
- The Copilot projects subsequent ordinary user turns from the same public Session stream and offers the last 24 discussion segments, including refreshed explicit references. Each answer retains its own evidence/actions. An ordinary follow-up cannot inherit the prior turn's `FRESH` badge or evidence basis. Explicit follow-up prepares the original referenced object, never the newly selected page implicitly.
- Source suggestions open the exact descriptor-authorized file in one review action, without first creating a draft journal. A pristine buffer can receive the AI change; an existing human buffer is never replaced. Each explicit review focuses the editable textarea, not the read-only historical source viewer.
- Unsaved editor buffers are Session/workspace/Job/role/file scoped, with bounded plugin-owned `sessionStorage` and visible memory-only/storage-failure handling. Switching files/views and refreshing recovers edits. First-edit source identity remains the save baseline; changed source requires explicit reconciliation. If historical/live identity mismatch disables editing, retained drafts remain copyable, with an explicit reload action.
- Expired proposal text remains readable. Reprepare converts the original Host-typed refs back into a strict UI context, preserving source lines, criteria/evidence, materialized selection, Compare/Gate identities and scope. Changed content or expired subsets return to the original page for explicit reselection; no filter rerun or silent scope expansion.
- Cards distinguish saved suggestions from applied changes and completed read-only comparisons. “Collapse suggestion” only collapses the card; it is not labelled “discard.” Narrow-screen collapsed Copilot shows reply-ready/running status.

## Acceptance rules

- A passing unit suite is not a passing product journey.
- Every reference must identify a Host-verified object; labels, DOM text, and model prose are not identity.
- The same DSH Conversation owns messages, approvals, cancellation, and results.
- Ask only prepares a visible draft. No automatic send, Job, Gate, deployment, or publication.
- Do not use private Host stores/events to emulate missing public contracts.
- Preserve historical identities, user drafts, credentials, and unrelated workspace changes.

## Explicit later-phase dependencies

Message-scoped automatic context and opening an unmounted Host view require supported DSH public contracts. Production pause/ramp/rollback requires an actual registered target, policy, RBAC, approvals, rollback and audit integration. Neither is represented as implemented by ordinary offline Harbor approvals.

Phase 1 now includes a registered bounded consumer with owned asynchronous processes and durable sequence journals. It still needs a working upstream Candidate execution runtime, complete Docker-resource reconciliation, transactional event publication and replay, and full actor/role/model/turn audit identity. Immediate draft/read actions use two records; diagnostic operations record their asynchronous transitions. Neither is an SSE/outbox implementation. New proposals/previews expire on process restart; completed records remain Session-owned and unknown running ownership is never automatically resumed.
